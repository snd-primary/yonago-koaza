# 指示書：e-Stat 小地域境界データの変換（米子市・大字マップ用）

## 背景・目的

米子市の「大字」の境界を Web 地図（MapLibre GL JS）に表示するアプリを作っている。
元データは e-Stat の国勢調査「小地域（町丁・字等別）境界データ」。
このデータを **Web 配信用の GeoJSON に変換する**のが今回の作業。

ただし、国勢調査の小地域は **大字と一致するとは限らない**（町丁単位の区域、秘匿のための合算区域、水面調査区などが混ざる）。
そのため、**変換の前にまず中身を調べて報告すること**。大字単位にまとめ直す（dissolve）かどうかは、報告を見て私が判断する。

## 入力

- `data/raw/` に e-Stat からダウンロードした Shapefile 一式（.shp / .shx / .dbf / .prj など）を置いてある
- `data/raw/` 内のファイルは **一切変更しないこと**
- ネットワークからデータを取ってこないこと（入力は上記のファイルのみ）

## ツール

- 基本は **mapshaper**（npm でローカルにインストールする。グローバルインストールはしない）
- 必要なら GDAL（`ogr2ogr` / `ogrinfo`）を使ってよい。入っていなければ、入れる前に私に確認すること
- 処理は **再実行できるスクリプト**にする（`package.json` の scripts か、シェルスクリプト）。手作業の手順を挟まないこと

## フェーズ1：調査（ここで一度止まって報告）

以下を調べて `data/report.md` にまとめること。

1. **座標系**：`.prj` の中身から判定する（推測で決めないこと）
2. **文字コード**：`.dbf` の属性が Shift_JIS なのか UTF-8 なのか。`.cpg` の有無も確認し、実際に名前が文字化けせずに読めることを確かめる
3. **基本情報**：フィーチャ数、属性フィールドの一覧（型と例となる値）、範囲（bbox）
4. **区域の種類**：`HCODE` の値ごとの件数。水面調査区など、通常の町丁・字以外のものがあれば列挙する
5. **秘匿・合算**：`KIGO_E` などの秘匿や合算を示すフィールドがあれば、値ごとの件数と、該当する区域の名前
6. **名前の一覧**：`S_NAME`（町丁・字等の名称）を全件、`KEY_CODE` 順に一覧にする
7. **名前のパターン分析**：
   - 「〇丁目」で終わるもの
   - 「大字」で始まるもの
   - 同じ名前が複数のフィーチャに分かれているもの（マルチパートや飛び地）
   - 「丁目」を取り除くと同じ名前になるグループ（大字単位にまとめる候補）
8. **ジオメトリの健全性**：不正なジオメトリ、自己交差、空のジオメトリがあるか

報告の最後に、**大字単位にまとめるとしたらどんなルールが考えられるか**を、候補として 1〜3 案書くこと（実行はしない）。

→ **ここで作業を止めて、私の確認を待つこと。**

## フェーズ2：変換（確認後に実施）

1. **座標系**：EPSG:4326（WGS84 緯度経度）に変換する
2. **文字コード**：UTF-8 で出力する
3. **除外**：水面調査区などを除外するかどうかは、フェーズ1の報告をもとに私が指示する
4. **属性**：残すのは以下の項目だけにして、名前を付け直す
   - `code`（KEY_CODE）
   - `name`（S_NAME）
   - そのほか、フェーズ1で必要と判断したもの
5. **簡略化**：mapshaper の `-simplify` を使う
   - 隣り合う区域どうしの境界線を共有したまま簡略化すること（隙間や重なりを作らない）
   - 小さい区域が消えないようにする（`keep-shapes`）
   - 簡略化の割合を何段階か試して、ファイルサイズと見た目を比べられるようにする
6. **座標の精度**：小数点以下 6 桁に丸める
7. **dissolve**：私が指示した場合のみ、指定したルールで大字単位にまとめたファイルを**別ファイルとして**出力する

## 出力

```
data/
  raw/                 # 入力（変更しない）
  report.md            # フェーズ1の報告
  out/
    shochiiki.geojson  # 小地域そのまま（簡略化済み）
    oaza.geojson       # dissolve 後（指示した場合のみ）
```

## 検証（フェーズ2の最後に必ず実施して、結果を報告すること）

- フィーチャ数：入力、除外後、出力のそれぞれ
- 簡略化の前と後で、全区域の合計面積がどれだけ変わったか
- 出力の bbox が米子市の範囲に収まっているか
- 不正なジオメトリが 0 件であること
- 名前が文字化けしていないこと（何件か抜き出して表示する）
- 出力ファイルのサイズ
- 確認用に、出力を簡単に目視できる HTML（MapLibre と地理院の淡色地図を背景にして GeoJSON を重ねるだけのもの）を `data/out/preview.html` として作る

## やらないこと

- アプリ本体の実装
- 小字や地番（筆）の扱い
- `data/raw/` の変更
- 私の確認なしに dissolve や除外の判断をすることå
